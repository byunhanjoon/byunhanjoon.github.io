Road to ICLR · Day 4 / 30

Same table,
different views

Three networks can read the same column in three equally valid ways. At matched compute, that diversity can be worth more than another random seed.

August 27, 2026Han Joon ByunExperiments and results ↗

Day 1 found exact states hiding inside numerical columns. Day 2 found that equivalent coordinates lead neural networks down different paths. Day 3 showed that this sensitivity is broad.

The Day 4 question. Can we turn representation sensitivity from a nuisance into useful diversity—without giving the method more models, parameters, or test-set choices?

One value can have several addresses

Suppose a column contains incomes. The raw value is the same in every row below. What changes is its address.

No chart is universally best. That is usually presented as a hyperparameter problem: choose one. But different charts also produce different mistakes. This suggests treating a representation like a camera angle rather than a winner-take-all setting.

An atom is visible, but not necessarily named

There was one loose end from Day 1. If many rows have exactly the same numerical value—an atom—do Q-PLE and T-PLE already handle it?

I held the exact-identity mechanism fixed and changed only the second model's chart: atom-aware T+Q versus atom-aware T+T. It improved validation log loss for MLP and ResNet, was effectively tied for FT-Transformer, and also helped an attention-plus-MLP hybrid.

MLP+0.372%
ResNet+0.916%
FT-Transformer−0.015%
Attention + MLP+0.293%
Atom lesson. Q-PLE and T-PLE can react to repeated values. A dedicated identity channel still changes the learning geometry—and chart diversity can help after identity is already present.

The controls removed three tempting stories

contrastive alignment1 / 6 winsBringing two whole-table views together blurred useful differences.
learned chart residualmatched by T-onlyThe extra network helped; the special chart was not the cause.
two-view fixed policy10 / 12 wins, gate failedOne tiny baseline loss made a 50/50 mixture too fragile.

The third failure suggested a small correction: keep two ordinary T-PLE members as ballast, and replace only the third. This also gives the cleanest possible control.

HeteroBag-3: replace one view, not one budget

I froze the rule and four new OpenML datasets before downloading their values or labels. There was no per-dataset view search and no test-dependent weight fitting.

The effect is modest, but unusually clean: +1.084% on classification, +0.602% on regression, and +0.843% overall. All six regression cells improve. More importantly, the result survives the control that killed the earlier multi-view story.

What survived Day 4

01Do not force agreement

Different views are useful because they disagree. Full-row contrastive alignment can erase the diversity we wanted.

02Compare against another seed

A second network is not evidence for a representation. Replace one member at fixed model count and compute.

03Separate atoms from order

Repeated numerical states may deserve identities; ordered charts still contribute a different inductive bias.

Day 4 conclusion. A table does not need synthetic rows to gain useful augmentation. Render the same rows through several defensible coordinate systems, preserve their disagreement, and spend an ensemble slot on representation diversity.

HeteroBag-3 is a candidate method, not a finished paper. One prospective panel and one seed triplet are not enough. The next test is a second frozen panel with multiple triplets, stronger tuned ensembles, and an automatic rule for when numerical atoms deserve identities. But Day 4 finally isolates a value that ordinary extra capacity does not explain.
