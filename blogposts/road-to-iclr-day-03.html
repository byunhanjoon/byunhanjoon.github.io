Road to ICLR · Day 3 / 30

Same table,
different predictor

A model should not care whether we put age before income, rename “gold” as 0, or measure dollars in cents. Sometimes the whole learning pipeline does care—and tuning can amplify the difference.

August 26, 2026Han Joon ByunExperiments and results ↗

Day 1 blurred the line between “numerical” and “categorical.” Day 2 showed that two encodings can contain the same information, yet lead a neural network down different learning paths. Day 3 began by stress-testing that effect. Equivalent coordinates changed initialization and optimization across 30 datasets—but my attempt to turn the effect into a better predictor lost to the simple control of training another seed.

That failure changed the question. Instead of asking which representation wins?, I began asking something more basic:

The new question. If we rewrite a table without changing what it means, does the final prediction stay the same?

This sounds like a low bar. In practice, it exposes a hidden source of uncertainty that ordinary train/test evaluation never sees.

One table has many spellings

Consider a small customer table. We can move its columns, replace category names with arbitrary IDs, or change the unit of income. Each version describes the same people. A reversible rewrite should be as harmless as changing a file’s font.

The rewrite must be honest. Renaming “gold” as 0 is harmless; pretending that 0 is closer to “silver” than to “bronze” is not. Converting dollars to cents is harmless; converting temperature without accounting for its offset is not. So the first step of the audit is always to declare which changes preserve the meaning of the task.

same meaningone semantic table÷arbitrary spellingsthe nuisance choices=the thing we care aboutthe table without formatting accidents

Mathematicians call this a quotient: we choose to treat all meaning-preserving spellings as one object. Here is the practical version: a result belongs to the table only if it survives the spellings we agreed should not matter.

Prediction wobble has an exact price

Run the complete pipeline once on each spelling and place its prediction on a line. If the dots overlap, the pipeline ignored the nuisance. If they spread out, the prediction depends on formatting luck.

The last term is the useful one. It is the portion of proper loss caused only by disagreement across equivalent spellings. Once the models have been fitted, it needs no test labels: we can measure it directly from their predictions. I call it schema risk.

This turns a vague complaint—“models are representation-sensitive”—into an auditable quantity. In the first conventional-model cells, averaging across spellings removed 0.21% to 1.13% of mean Brier loss. The hard predicted label changed for 2.3% to 11.6% of rows. In same-seed neural comparisons, the corresponding tax ranged from 0.63% to 8.20%.

Now we can ask who caused it

A table has several arbitrary choices at once. We can vary feature order, category IDs, class IDs, units, or a coordinate basis independently. The result is a grid of predictions. Functional ANOVA then divides the wobble into causes.

This matters because it tells us where to intervene. A model may be robust to category codes but sensitive to column position. Or two choices may become dangerous only in combination. We can also cross these schema choices with ordinary randomness such as the train/validation split or initialization seed.

That cross revealed a recurring pattern: much of the neural instability was not “the chart” or “the seed” alone. The chart × seed interaction explained 54%–65% of their joint prediction variance. The spelling changed which random training runs succeeded.

Which invariances did the models already have?

There is an important objection to test before blaming a model family: trees and native categorical learners already ignore some rewrites by construction. So I ran a separate one-factor-at-a-time audit on Adult, Churn, and Otto. It crossed six pipelines with feature order, category IDs, aligned class IDs, and positive affine unit changes. The semantic split stayed fixed; each row used 2,000 training and 750 test examples.

First I chose a configuration on the reference spelling and froze it across the other views. Only afterward did I rerun validation selection. This separates the fitted learner changed from the tuning decision changed.

The objection was right for category spelling. Native CatBoost and native HistGB were exactly invariant to every tested category-ID permutation. The forest result came from the deliberately ordinal pipeline: it fed arbitrary IDs to numerical thresholds, so renaming a category changed the partitions the learner could express. One-hot encoding removed that false order, but its forest still moved slightly because the concrete tree builder can couple random tie-breaking to derived column positions.

The other rewrites still reached real pipelines. Feature order changed every forest family and CatBoost, plus multiclass HistGB on Otto. Binary class reversal changed HistGB and CatBoost after their output columns were aligned, while the forests did not move. Histogram boosting ignored every tested unit conversion exactly; raw forests did not, even though an ideal axis-aligned tree admits the same rank partitions. That last gap belongs to finite training arithmetic and implementation details, not to the abstract tree function class.

Tuning is part of the model

So far, imagine keeping one training recipe fixed. Real pipelines do more: they try several recipes on validation data and choose a winner. That selection step can react to the spelling too.

This creates a subtle tradeoff. Tuning separately for every spelling may improve average accuracy, while making equivalent versions of the same table disagree more.

In the expanded one-factor audit, validation changed its choice in 12 of 66 applicable dataset × pipeline × rewrite cells. One-hot logistic and HistGB never switched; no unit rewrite switched any family. The switches were concentrated in feature order, ordinal category codes, and binary class IDs. A stable choice still did not imply stable predictions—HistGB is the clearest example.

The tuning rule is therefore part of the predictor—not backstage bookkeeping. If changing column order changes which hyperparameters win, it can change the final model twice: once through training, and again through model selection.

same spelling→validation scores→chosen recipe→prediction

Change the spelling and every arrow can move.

The effect was structured, not universal

Across the small Adult/Churn/Otto panel, forests switched somewhere on all three datasets, CatBoost on two, and histogram gradient boosting on none. This is evidence of family structure—not an estimate of how often all tabular models switch.

A repair suggested by the diagnosis

If selection is overreacting to one spelling, do not let one spelling cast the deciding vote. Evaluate each candidate recipe on a small development menu of equivalent spellings, average its validation loss, choose once, and freeze that choice across the rest.

This is not a free improvement. Pooling reduced risk for most individual menus—228/252, 180/252, and 198/252—but not every one. Mean Brier loss also became worse on most held-out splits. The honest result is an accuracy–stability frontier, not a universally better tuning algorithm.

The audit needs its own audit

Even the word “average” needs a declaration. Uniformly weighting all spellings asks, “How stable am I under an even draw?” If real deployments favor some spellings, the answer changes. Under moderate adverse reweighting, favorable split counts fell from 7/7 everywhere to 7/7, 4/7, and 5/7.

The estimand has to include the distribution. There is no context-free number called “the schema risk.” There is schema risk under a declared set of harmless rewrites and a declared way of weighting them.

Meaning cannot be tuned into existence

A final experiment sharpened the boundary. For an ordered field, nearby values really are neighbors; for a cyclic field, the ends meet; for a nominal field such as color, any path through the categories is invented.

With fixed strength, the correct path or ring beat a deliberately permuted geometry in all 18 ordered and cyclic cells, while the neutral geometry beat every false topology in all nine nominal cells. That looked reassuring.

Then I let validation tune the strength. False paths, rings, and permuted paths beat the neutral model in 8/9, 8/9, and 9/9 nominal cells. Search had exploited accidental adjacency. It had not discovered meaning.

metadata→choose the semantic family→validation→tune within that family

The order matters. Validation can choose how strongly to trust a declared geometry. It cannot tell us whether “red” is truly next to “blue.” Semantics must enter as metadata, not emerge from a hyperparameter sweep.

What survived the experiments

The point of running many probes was not to preserve them all. It was to let weak stories die and keep the few claims that became clearer under pressure.

SURVIVEDA measurable pipeline risk
  • Equivalent spellings can change fitted predictions.
  • The resulting proper-loss tax is exact and label-free after fitting.
  • The tax can be attributed to schema choices and their interactions.
  • Pooling validation evidence can target selection-induced risk.
DID NOT SURVIVEA universal performance trick
  • The representation ensemble lost to another ordinary seed externally.
  • Four apparent architecture-ranking reversals vanished with 13 more seeds.
  • Pooled selection does not dominate on both accuracy and stability.
  • Validation cannot infer category semantics from arbitrary IDs.

This leads to a different paper than I expected at the start of Day 3. It is not “here is the best tabular encoding.” It is an audit of whether a claimed result is identifiable from the table’s meaning—or partly determined by arbitrary coordinates.

Day 3 conclusion. The model is not just its architecture and weights. It is the entire path from schema to preprocessing, tuning, training, and prediction. If harmless rewrites change that path, the variation belongs in the reported uncertainty—not behind one lucky table spelling.
Technical notes and statistical boundaries

For squared loss and multiclass Brier loss, the displayed decomposition is the Hilbert-space identity Ez‖pz−y‖² = ‖Ezpz−y‖² + Ez‖pz−Ezpz‖². Output classes are aligned before comparison.

The invariance matrix uses one reference plus up to three nonidentity views per factor, a predeclared 10−10 tolerance, and one semantic split. Its 66 applicable cells are controlled diagnostics, not independent prevalence samples. Code, configuration, raw results, and the complete numerical report are in the experiment directory.

The Adult/Churn/Otto family panel is a 3 × 3 pilot and should not be read as population prevalence. The three seven-split confirmation cases were selected because they were unstable on an earlier split. Exact tests treat the split—not the row or overlapping menu—as the replication unit.

The 29.2%, 37.5%, and 34.7% repair results average all 36 balanced development-menu partitions within each split. Individual menus overlap, so 252 menu outcomes are not 252 independent trials. Sensitivity to the menu distribution remains part of the result.
