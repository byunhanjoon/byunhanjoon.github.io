When “numerical” and “categorical” aren’t types

A column’s storage type is not its learning semantics. What if a tabular model began with several plausible views of every feature—and let the data decide which ones matter?

August 24, 2026 Han Joon Byun Code & results on GitHub ↗

Most tabular pipelines begin with a deceptively small decision: every column is declared numerical or categorical. That decision controls almost everything that follows. A number may be standardized and projected; a category may be mapped through a lookup table. From that point on, the backbone is expected to repair whatever the schema got wrong.

But a dtype is a storage convention, not a semantic law. ZIP codes are numbers with almost no metric meaning. Star ratings are categories with a strong order. Month, dosage band, education level, room count, and discretized age all live somewhere between identity and magnitude.

Starting hypothesis. For mixed tabular data, preprocessing should be treated as a small hypothesis class—not a single irreversible choice. The experiments below will reject this broad version and reveal a narrower, more useful one.

A continuum hiding inside a checkbox

The usual binary schema is useful, but it bundles together several different questions. Does distance between values mean anything? Is there an order? Do neighboring values behave similarly? Is the feature mostly an identifier? Does its meaning change in the presence of another feature?

Those questions do not produce a clean partition. They produce a semantic profile. Try the examples below.

Where the split enters the model

This distinction is not merely philosophical. In FT-Transformer, for example, a numerical feature is tokenized with a feature-specific linear projection, while a categorical feature uses a lookup table.[2] TabTransformer concentrates its contextual embeddings on categorical features, then combines them with continuous inputs downstream.[3] These are sensible designs—but the route is chosen before learning begins.

Meanwhile, numerical feature embeddings have become surprisingly important. Piecewise-linear encoding (PLE) and periodic embeddings can materially improve a range of tabular neural backbones, sometimes allowing an MLP to compete with a Transformer.[4] That result suggests a broader possibility: perhaps the representation in front of the backbone deserves at least as much attention as the backbone itself.

Recent representation work has made the numerical side much richer, while the categorical side in representative architectures still often begins with a lookup table or contextualized identity embedding. The imbalance is understandable—category embeddings are already expressive—but it leaves ordered, quasi-continuous, and target-structured categories with fewer explicit inductive biases.

The candidate: preprocess uncertainty

Instead of assigning one route to feature j, construct a small set of views and mix them:

zⱼ = αᵢd eⱼ(xⱼ) + αₚₗₑ pⱼ(xⱼ) + αᵣₐw rⱼ(xⱼ) + αₜgₜ tⱼ(xⱼ)

Here, e is an identity-preserving embedding, p is a piecewise-linear view, r is a standardized or ranked scalar view, and t is a target-aware statistic. The coefficients could be fixed by validation, produced by a small gate, or regularized toward a single route.

Target encoding is tempting because it can reveal an order among categories. But naïvely computing a category’s target mean leaks the answer into its own representation. CatBoost’s ordered target statistics are an important warning and a useful template: target-aware preprocessing must respect training order or use honest out-of-fold estimates.[5] Applying PLE after such an estimate is plausible, but only if the whole two-stage pipeline remains leakage-safe.

The harder extension is relational. A category may look unordered alone and become ordered conditional on region, age, or product family. Explicit pair encodings could surface this early, but naïve crosses explode in cardinality. A useful method would need selective, factorized, or strongly regularized feature combinations—not a brute-force Cartesian product.

A first synthetic probe

Before training a large neural network, I built a deliberately small representation test. It creates three discrete features: a number with non-monotonic category behavior, a declared category with a smooth ordinal effect, and a hybrid feature with both a trend and level-specific residuals. Every method uses the same ridge readout, so the only difference is what the preprocessing exposes.

0.701 RMSEMulti-view at 2,500 rows, versus 1.173 for schema-only and 0.698 for the semantic oracle.

This result is a sanity check, not confirmation. The generator was designed to contain the ambiguity the encoder addresses, and a linear readout is not a modern tabular backbone. What it does establish is that “let the model figure it out” can be a needlessly hard request when the input representation has already erased plausible structure.

The synthetic experiment code is intentionally short and dependency-light. Reproducing the chart requires only NumPy.

From a toy probe to four real datasets

A synthetic generator can show that the mechanism is possible, but it cannot show that real tables contain enough semantic ambiguity for the mechanism to matter. For the next test, I am borrowing data and split conventions from TabPack: Efficient Hyperparameter Ensembles for Tabular Deep Learning.[6] TabPack evaluates 17 medium-to-large datasets; running all 17 would broaden coverage, but it would not make this first question sharper.

I instead chose four datasets before inspecting the Day 1 results. Three offer different reasons for expecting ambiguous feature semantics, and the fourth is a negative control.

The comparison that matters

The weak comparison is multi-view versus raw numerical inputs. PLE is already known to help numerical features, so that result would say little about feature identity. The decisive comparison is against a schema + PLE baseline:

SchemaQuantile-normalized numerical values, binary values, and one-hot categorical identities.
Schema + PLEThe same front end with piecewise-linear views for every numerical feature.
Multi-viewAdd identity views for low-cardinality numbers and leakage-safe target-ordered views for categories.

All three routes feed the same fixed MLP. A numerical column receives an identity view only when it has at most 32 distinct training values. Each categorical target statistic is smoothed and five-fold cross-fitted: a training row is encoded by a map that did not see its target, while validation and test encodings average the corresponding fold maps. No preprocessing step sees test labels.

The protocol uses the released train/validation/test split for each dataset, early stopping on validation performance, and five training seeds. I report mean and standard deviation of test accuracy or RMSE, along with input dimensionality, parameter count, and wall-clock time. The primary result is the average normalized improvement of multi-view over schema + PLE across the four datasets; per-dataset wins are secondary. The full download and benchmark scripts are in the repository.

Precommitted reading. Improvement over schema alone is not enough. If multi-view does not reliably beat schema + PLE—or if any gain disappears after accounting for parameters and variance—the broader semantic-routing hypothesis has not earned support.

The broad version of the hypothesis fails this first real-data test. Multi-view beats schema + PLE only on Black Friday, ties it exactly on California, and loses on Adult and Diamond. California is an implementation check as well as a control: because it has no categorical or ≤32-cardinality numerical columns, schema + PLE and multi-view are the same representation and produce identical runs.

Diamond is the most informative failure. It looked like the easiest win because cut, color, and clarity are ordered. Instead, the target-derived categorical views hurt in every paired seed. One plausible explanation is confounding: a category's mean price reflects the distribution of carat and other numerical drivers, not only the category's intrinsic order. Another is simpler—the extra 49 input dimensions and their noisy cross-fitted estimates make optimization harder. These are hypotheses prompted by the result, not explanations established by it.

The next ablation should therefore be narrow: compare known ordinal ranks, raw target means, and target means of residuals after a numerical-only model; then add a sparse gate and a parameter-matched PLE control. Until one of those variants beats schema + PLE across seeds, the reliable Day 1 result is about numerical representation, not a general learned continuum between numerical and categorical identity. Per-seed scores are in real_results.csv.

A second pass: routing helps performance, but the control matters

I then ran that narrower ablation. The new suite separates numeric identity, raw categorical target means, residual target means, diagnostic selection, sparse gating, and validation-greedy late fusion. Every single model is matched to the parameter count of schema + PLE. I screened PLE with 8, 16, 32, 64, and 128 bins on seed 0 validation performance, fixed 64 bins for Diamond and 128 for Black Friday, and ran the selected configurations over five seeds.

Performance is better, but the controls prevent the easy interpretation. On Diamond, the sparse gate improves over plain PLE by 0.88% and wins four of five paired seeds. Yet the gate gives only about 1.9% total weight to the two residual categorical routes, and the PLE-only gated control already improves by 0.77%. Sparse gating beats that architecture-matched control by just 0.10% on average and in two of five seeds. Most of the apparent gain comes from projecting schema and PLE separately—not yet from learning categorical order.

Black Friday tells a different story. Late fusion improves RMSE by 0.57% and wins all five paired seeds. Its greedy ensemble repeatedly retains the PLE and numerical-identity models, often adding the individually weak residual model for complementary errors. This is useful performance, but it costs two or three models and therefore is not parameter matched. A three-member PLE-only deep ensemble is now the required control.

Neither result yet establishes that learned numerical–categorical semantics—not ordinary architectural or ensemble diversity—caused the gain. The full 150-run record is in expanded_results.csv.

The narrow signal: some numbers contain atoms

The failed routes in the experiment log suggest a more precise question. PLE and identity encoding do not merely offer two implementations of the same idea. They make different assumptions: PLE asks what nearby values should share; an identity view asks what an exact value should remember.

This matters for integers that are only partly metric. Forty hours per week is close to 39 and 41, but it may also identify a qualitatively different population. A product code of 2 may not be meaningfully “between” codes 1 and 3 at all. Treating every such column as continuous is as dogmatic as treating every number as a category.

The selection rule follows directly from that intuition. First, a numerical-only model makes out-of-fold predictions using normalized values, PLE, and binary features. I then group its residuals by each feature's exact values.

?After the smooth model has made its best prediction, do its errors still line up by exact value?If exact-value groups explain at least 0.1% of the remaining residual variance, the column receives an additional identity view. The view itself is target-free; only this training-only selection rule uses labels.

With that mechanism fixed, I ran 397 fits across four datasets. The search tuned PLE resolution and the backbone, compared identity, residual, and gated routes, froze every seed-0 validation choice, and only then confirmed the selected models over five test seeds. The most surprising contrast is not between model families; it is between datasets. Diamond's explicitly ordered categories looked like the easiest semantic win, yet none survived the controls. Adult and Black Friday improve instead when columns stored as numerical receive identity views. The schema's consequential mistake was not calling an ordered variable “categorical.” It was assuming that every number must obey numerical geometry.

Adult makes the signal tangible. The diagnostic selects capital gain, capital loss, and hours per week. These are not ordinary smooth measurements: each distribution contains an atom—a value occupied by an unusually large fraction of the dataset.

The identity-only control reaches 0.8714 ± .0014, 1.19 accuracy points above the tuned PLE backbone, and wins every paired seed. That removes residual categorical target encoding from the explanation. It does not yet tell us whether full identity encoding is necessary—or whether three simple indicators for gain = 0, loss = 0, and hours = 40 would recover the same gain.

Black Friday shows the same pattern at smaller scale: identity views for all four numerical columns reduce RMSE by 0.21% and win all five paired seeds. Categorical target and residual routes, despite being more elaborate, never provide the reliable cross-dataset gain.

TabPack-style hyperparameter ensembles are strong—especially on Diamond and California—but answer a different question. Their gains establish useful model diversity, not feature semantics, because several selected members are ordinary schema + PLE models.

Day 1 conclusion. The universal multi-view hypothesis is false. A narrower idea survives: a numerical feature can have a smooth background and a few important atoms, so it may need both PLE and a sparse exact-value correction. The signal is large on Adult, small on Black Friday, and absent on Diamond and California. Full screening and frozen five-seed results are in signal_search/.

What would falsify the idea?

The next step is not to add more machinery. It is to find the smallest set of tests capable of killing the hypothesis.

  1. Mechanism test. Which selected column causes the gain, and can simple mode indicators match a full identity view?
  2. Split-stability test. Does the diagnostic select the same columns under new data splits—not merely new initialization seeds on one split?
  3. Generalization test. Does the correction survive matched MLP, ResNet, and Transformer backbones while handling rare or unseen values?

If the indicators explain everything, the useful object is not a generic identity view but a compact point-mass basis. If the result disappears across splits, Day 1 found a split-specific curiosity. Either outcome sharpens the next experiment.
