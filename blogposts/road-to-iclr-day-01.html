When “numerical” and “categorical” aren’t types

A column’s storage type is not its learning semantics. What if a tabular model began with several plausible views of every feature—and let the data decide which ones matter?

August 24, 2026 Han Joon Byun Code & results on GitHub ↗

Most tabular pipelines begin with a deceptively small decision: every column is declared numerical or categorical. That decision controls almost everything that follows. A number may be standardized and projected; a category may be mapped through a lookup table. From that point on, the backbone is expected to repair whatever the schema got wrong.

But a dtype is a storage convention, not a semantic law. ZIP codes are numbers with almost no metric meaning. Star ratings are categories with a strong order. Month, dosage band, education level, room count, and discretized age all live somewhere between identity and magnitude.

Day 1 hypothesis. For mixed tabular data, preprocessing should be treated as a small hypothesis class—not a single irreversible choice. Giving each ambiguous feature several structured views may reduce the amount of semantic repair we ask the neural backbone to discover from scratch.

A continuum hiding inside a checkbox

The usual binary schema is useful, but it bundles together several different questions. Does distance between values mean anything? Is there an order? Do neighboring values behave similarly? Is the feature mostly an identifier? Does its meaning change in the presence of another feature?

Those questions do not produce a clean partition. They produce a semantic profile. Try the examples below.

Where the split enters the model

This distinction is not merely philosophical. In FT-Transformer, for example, a numerical feature is tokenized with a feature-specific linear projection, while a categorical feature uses a lookup table.[2] TabTransformer concentrates its contextual embeddings on categorical features, then combines them with continuous inputs downstream.[3] These are sensible designs—but the route is chosen before learning begins.

Meanwhile, numerical feature embeddings have become surprisingly important. Piecewise-linear encoding (PLE) and periodic embeddings can materially improve a range of tabular neural backbones, sometimes allowing an MLP to compete with a Transformer.[4] That result suggests a broader possibility: perhaps the representation in front of the backbone deserves at least as much attention as the backbone itself.

Recent representation work has made the numerical side much richer, while the categorical side in representative architectures still often begins with a lookup table or contextualized identity embedding. The imbalance is understandable—category embeddings are already expressive—but it leaves ordered, quasi-continuous, and target-structured categories with fewer explicit inductive biases.

The candidate: preprocess uncertainty

Instead of assigning one route to feature j, construct a small set of views and mix them:

zⱼ = αᵢd eⱼ(xⱼ) + αₚₗₑ pⱼ(xⱼ) + αᵣₐw rⱼ(xⱼ) + αₜgₜ tⱼ(xⱼ)

Here, e is an identity-preserving embedding, p is a piecewise-linear view, r is a standardized or ranked scalar view, and t is a target-aware statistic. The coefficients could be fixed by validation, produced by a small gate, or regularized toward a single route.

Target encoding is tempting because it can reveal an order among categories. But naïvely computing a category’s target mean leaks the answer into its own representation. CatBoost’s ordered target statistics are an important warning and a useful template: target-aware preprocessing must respect training order or use honest out-of-fold estimates.[5] Applying PLE after such an estimate is plausible, but only if the whole two-stage pipeline remains leakage-safe.

The harder extension is relational. A category may look unordered alone and become ordered conditional on region, age, or product family. Explicit pair encodings could surface this early, but naïve crosses explode in cardinality. A useful method would need selective, factorized, or strongly regularized feature combinations—not a brute-force Cartesian product.

A first synthetic probe

Before training a large neural network, I built a deliberately small representation test. It creates three discrete features: a number with non-monotonic category behavior, a declared category with a smooth ordinal effect, and a hybrid feature with both a trend and level-specific residuals. Every method uses the same ridge readout, so the only difference is what the preprocessing exposes.

Schema onlyRaw standardized views for declared numbers; one-hot for the declared category.
Semantic oracleThe correct view is chosen using knowledge of the synthetic data-generating process.

0.701 RMSEMulti-view at 2,500 rows, versus 1.173 for schema-only and 0.698 for the semantic oracle.

This result is a sanity check, not confirmation. The generator was designed to contain the ambiguity the encoder addresses, and a linear readout is not a modern tabular backbone. What it does establish is that “let the model figure it out” can be a needlessly hard request when the input representation has already erased plausible structure.

The experiment code is intentionally short and dependency-light. Reproducing the chart requires only NumPy.

What would falsify the idea?

The next step is not to add more machinery. It is to find the smallest set of tests capable of killing the hypothesis.

  1. Backbone test. Does multi-view encoding still help MLP, ResNet, and FT-Transformer baselines once capacity and tuning budgets are matched?
  2. Ambiguity test. Are gains concentrated in features whose raw, ordinal, and identity views disagree—or does extra dimensionality explain them?
  3. Leakage test. Can ordered or cross-fitted target views improve results without optimistic validation bias?
  4. Interaction test. Can a selective pair encoder discover conditional order without a cardinality explosion?
  5. Simplicity test. Does a learned gate beat plain concatenation after accounting for parameters, latency, and variance?

If the answer to these questions is mostly “no,” the binary split may be a useful inductive bias rather than a bottleneck. If the answer is “yes,” then preprocessing is not merely cleanup. It is the first learned theory of what a table means.
