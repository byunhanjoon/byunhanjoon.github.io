Road to ICLR · Day 9 / 30

The model saw the grid, not just the dots.

The dots stayed put. The grid turned. A person saw the same pattern—but the model changed its mind.

September 1, 2026Han Joon Byun

A table is a description of reality. A medical model never meets a patient; it sees columns. A lending model never meets a borrower; it sees numbers. This makes a quiet question surprisingly important:

If we rewrite the same facts without changing their meaning, should the answer change?

For a dependable model, usually not. Day 9 tested that idea with the simplest rewrite I could think of: keep every point and every distance, but turn the invisible graph paper underneath them.

One reality, many descriptions

Drag the slider. The points rotate together, so their pattern never changes. Only the directions used to describe them do.

Across 11 real datasets and five very different kinds of models, this was not a corner case. Nearly three quarters of the model–dataset pairs changed enough to cross the study's preset threshold.

INSIGHT 01

The representation is part of the model. A learner never sees “the thing itself.” It sees one chosen description of it.

How the grid enters the answer

Learning is a journey from a rough first guess to a final rule. Many training algorithms take different-sized steps along different axes. Turn those axes, and the journey can bend—even when the prediction problem is unchanged.

I checked this mechanism by forcing two learners to begin with exactly the same predictions. A simple training rule kept the answers together. A widely used adaptive rule pulled them apart again. The difference was being created during learning; it was not evidence that one table contained more facts.

INSIGHT 02

Equivalent inputs need not create equivalent learning paths. The coordinate grid acts like a hidden preference over which solutions are easy to reach.

Describe relationships, not directions

There is another way to locate a point. Instead of saying “three units east and two units north,” say how it relates to familiar landmarks. Turn the map and east changes on the page; the landmarks do not move relative to one another.

The landmark description made the tested models perfectly stable to these rotations. But it also exposed a deeper tension: on some tables, accuracy became worse. The arbitrary-looking original axes had sometimes become useful shortcuts.

So “make everything invariant” is not the right principle. Stability is valuable only while it preserves what helps prediction.

INSIGHT 03

Invariance is a budget, not a virtue. Remove irrelevant variation—but stop when removing it begins to erase useful clues.

A dial, not a switch

The final method kept both readers: one sees the original columns; the other sees stable landmark relationships. A small practice set turns the dial toward stability only while prediction quality remains safe.

The dial is the important idea. It refuses a false choice between “trust the coordinates” and “ignore them.” When the stable view helps, use it strongly. When it becomes costly, back away.

Three ideas I want to keep

01Define what “the same” means

Robustness begins with a promise: which rewrites should preserve the answer?

02Test descriptions like software

Turn the grid, change the units, rename the states. Meaning-preserving rewrites are unit tests for models.

03Preserve the option to retreat

A stable view is safest when the model can fall back before stability harms the task.

Day 9 conclusion. The coordinate system is not the territory. Yet a learner can quietly treat it as evidence. The best remedy was not to erase coordinates, but to place a stable relational view beside them—and let observed performance decide how much trust each view receives.
